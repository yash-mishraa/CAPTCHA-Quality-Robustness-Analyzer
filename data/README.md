# Data and Artifact Policy

This repository keeps **code, configuration, and documentation** in Git and
keeps **generated bytes** out of Git. The goal is a clone that can regenerate
any committed result without downloading large opaque blobs.

## Directory contract

| Path | Contents | Tracked in Git? |
| --- | --- | --- |
| `data/raw/` | Generated clean and degraded images, plus per-run manifests | No (only `.gitkeep`) |
| `data/processed/` | Generated datasets: manifests, split tables, feature tables, images | No (only `.gitkeep`) |
| `data/interim/` | Temporary intermediate products | No |
| `data/external/` | Manually obtained third-party inputs | No |
| `models/` | Checkpoints, serialized models, model cards, embeddings | No (only `.gitkeep`) |
| `reports/` | Generated figures, HTML/PDF reports, metrics dumps, benchmark tables | No (only `.gitkeep`) |
| `configs/` | Human-authored generation and experiment configs | Yes |
| `docs/` | Methodology, overview, experiment log | Yes |

Generated outputs are reproducible from configuration + seed + code revision.
A small number of curated examples may be force-added later if they are needed
for documentation; that must be a deliberate, reviewed decision, not a default.

## What must never be committed

- API keys, access tokens, passwords, cookies, or private environment files.
- Personal data, human-solver responses, or anything collected without consent.
- Images or text captured from live third-party CAPTCHA services.
- Fonts or assets whose licences do not permit redistribution.
- Large model checkpoints or datasets.

## Generated dataset layout

Each generated dataset lives in `data/processed/<dataset-name>_<version>/`:

```text
manifest.csv           # public: one row per clean/corrupted sample; no raw text
sources.csv            # one row per clean source, with split and clean hash
ground_truth.csv       # INTERNAL: source_id,text (never in the public manifest)
features.csv           # sample_id + eight documented handcrafted features
dataset_summary.json   # counts, per-split summaries, split policy, artifact hashes
images/
  clean/<source_id>.png
  <corruption-family>/<sample_id>.png
```

The directory is written through a sibling `.partial` staging directory and
renamed into place only on success. It is Git-ignored and reproducible from the
committed configuration.

## Dataset versioning

Each generated dataset has:

1. A **generation config** committed under `configs/` (fonts, charset, text-length
   distribution, image size, background policy, corruption ladders, split rules,
   seeds, dataset version).
2. A **public manifest** recording, per sample: stable `sample_id`, `source_id`,
   `variant_id`, `split_group_id`, `split`, text length, font ID, render/variant
   seeds, corruption family and severity, numeric parameters, relative image and
   reference paths, SSIM/PSNR targets, content hashes, dataset version, and the
   generation config hash.
3. A **generation config hash** plus artifact hashes (manifest, sources, ground
   truth, features, and the image-pixel hash set) in `dataset_summary.json` and
   in the experiment log.

**Text policy.** Raw text is deliberately excluded from `manifest.csv`,
`sources.csv`, and `dataset_summary.json`. `text_sha256` is public; the raw string
is kept only in the internal, Git-ignored `ground_truth.csv` for reproduction and
verification. This keeps the public manifest free of stored CAPTCHA answers while
preserving reproducibility.

Prefer regenerating data from a config and manifest over committing images. If a
dataset must be shared, use an external artifact store or Git LFS deliberately;
do not silently add binaries to the main repository.

## Split integrity

Splits are assigned by **clean source** (`source_id`), not per image. All clean
and corrupted variants of a source share one `split_group_id` and one split, so
near-duplicates never cross train/val/test boundaries. The split ratios and seed
are declared in the config before generation; `dataset_summary.json` records the
ratios and a stable `split_policy.assignment_sha256`.

The committed reference dataset uses a random grouped split over synthetic
sources. This is **not** evidence of cross-generator or cross-font
generalisation. Milestone 3 adds a primary held-out-font stress test (Times New
Roman excluded from fitting and validation); it is still only a three-font,
same-renderer test, not broad real-world generalisation.

## Conventional benchmark artifacts

Milestone 3 writes two Git-ignored trees:

```text
reports/benchmark_v0_1_0/
  benchmark.md                 # generated protocol/results report
  model_comparison.csv         # train/validation only; no test tuning columns
  family_test_metrics.csv      # one test row per family winner + naive
  primary_predictions.csv
  metadata_experiments.csv
  performance_gaps.csv
  stratified_metrics.csv
  coverage_groups.csv
  feature_correlations.csv
  residual_summary.csv
  heldout_font_candidates.csv
  heldout_font_metrics.csv
  heldout_font_stratified.csv
  heldout_font_predictions.csv
  uncertainty.csv
  run_metadata.json            # hashes, versions, seeds, artifact hashes

models/benchmark_v0_1_0/
  primary_model.joblib         # selected image-only model (+ train-only scaler)
  primary_model_card.json      # feature schema, target, hashes, metrics
  heldout_font_model.joblib    # selected without Times New Roman
  heldout_font_model_card.json
```

The JSON cards are the source of truth for feature order, target, dataset
generation hash, split-assignment hash and artifact SHA-256. `joblib` is
scikit-learn's documented persistence format but is **not** safe for untrusted
files; only load artifacts generated locally. `captcha-benchmark verify-model`
checks the cards and performs an eight-feature smoke prediction.

## M4A occlusion/interference pilot artifacts

The M4A feasibility pilot is separate from the frozen reference dataset and the
M3 benchmark. It reads the frozen `v0.1.0` sources without modifying them and
writes:

```text
data/processed/occlusion_interference_pilot_v0.1.0/
  manifest.csv                 # one row per clean/corrupted pilot sample
  sources.csv                  # frozen split/font provenance + pilot clean paths
  features.csv                 # sample_id + the same eight features
  pilot_summary.json           # config, hashes, determinism, verification, gate
  images/
    clean/<source_id>.png
    thin_lines/<sample_id>.png
    arc_strokes/<sample_id>.png

reports/robustness_pilot/
  pilot.md                     # feasibility report
  level_summary.csv
  uncertainty.csv
  trend_by_source.csv
  trend_violations.csv
  feature_summary.csv
  feature_effect_sizes.csv
  feature_distinctness.csv
  feature_target_correlations.csv
  saturation.csv
  gate_results.json
  examples_thin_lines.png
  examples_arc_strokes.png
```

The pilot manifest records the exact stroke geometry, seed, width, intensity,
targets and image/reference hashes. Verification replays every corrupted image
from the recorded geometry. These artifacts are Git-ignored and are **not**
part of the frozen dataset or its test split. Regenerate with
`captcha-robustness-pilot run --config
configs/robustness_pilot_occlusion_v0_1_0.toml`.

## Retention and cleanup

- `data/raw/` and `data/processed/` are safe to delete; regenerate from configs.
- `models/` artifacts are disposable unless referenced by a logged experiment
  (`EXP-0003` references the benchmark cards); regenerate rather than commit.
- Logs and caches are disposable at any time.
